# Agent 空闲前等待活动资源排空

[English](guide.md) | 中文

## 变更

`Agent.activity` 可选地暴露精确的当前 `AgentActivity`。`undefined` 表示实现不支持该契约；`null` 表示当前没有活动。其准入 signal 与操作取消 signal 分离。driver 和维护任务退出时，先中止准入，再等待作用域内全部 `agent/activity-draining` 监听器，最后才清除活动或启动替代工作。维护期间公开状态保持 `idle`；通过 `activity` 与 `whenIdle()` 观察静止。排空期间，包括错误和取消路径，活动身份保持不变。成功完成不会仅为释放资源而取消操作。

排空失败仍通过 `whenIdle()` 和句柄销毁暴露，并阻止以正常空闲状态重新开放准入。普通活动结束，包括原因是 disposed 的取消，不会永久销毁 Agent；真正销毁句柄才永久关闭准入。

同步的临时维护竞争现在抛出导出的 `AgentActivityBusyError`。永久销毁和保留的排空失败不会使用这个重试信号。

本地子代理 activation 的 `result` 现在会在清理后拒绝保留的本地排空或句柄清理失败，除非此前的结果捕获或静止等待失败已是首要错误。`dispose()` 仍保留聚合的清理失败。发给父代理的内容仍使用已捕获的输出或通知；外部后端保留已捕获结果的策略不变。

## 迁移

1. 资源提供方必须认证精确的存活 Agent，捕获其精确活动，并拒绝不支持、缺失或已退役的活动，不能从 Agent 或 Session id 推断权限。使用活动 signal 关闭资源准入，不要与单次操作的取消 signal 混淆。
2. 在作用域内的 `agent/activity-draining` 事件中等待资源清理。等待任一清理前，先关闭该活动全部资源的准入，再汇合迟到的资源获取和已开始的操作。普通完成只退役匹配活动；永久 Agent 退役留给真正销毁。监听器不能等待所属 Agent 的 `whenIdle()` 或销毁，否则会等待自身。
3. 维护重试循环应专门捕获 `AgentActivityBusyError`，不要解析错误消息，也不要重试所有同步异常。除同步准入错误外，还需观察返回的维护 Promise；保留的排空和销毁失败需要清理或错误处理，而不是重试循环。
4. 本地子代理调用方必须观察 `result` 的拒绝，即使清理前已捕获答案。显式请求销毁时仍需观察 `dispose()`。父代理收到通知并不证明资源清理成功。

该契约本身不增加浏览器任务提供方、自动化 Tool、原生权限或人工接管确认。
